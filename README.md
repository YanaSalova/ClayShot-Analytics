
# ClayShot Analytics

ML-система для автоматического анализа тренировочных видео по стендовой стрельбе.

Система детектирует мишени на видео, определяет их состояние и на основе последовательности состояний рассчитывает количество попаданий. Результаты обработки нескольких видео агрегируются с помощью Apache Spark.

## Pipeline

```text
Video
  ↓
Frame extraction
  ↓
YOLO11 inference
  ↓
CSV logs
  ↓
Spark processing
  ↓
Hit statistics
```

## 1. Подготовка и разметка данных

Для формирования обучающей выборки были отобраны видеофрагменты с различными состояниями мишеней.

Видео были разбиты на отдельные кадры, после чего изображения вручную размечены в `Label Studio`.

Использовались четыре класса:

* `dark_entire` — тёмная целая мишень;
* `dark_broken` — тёмная разбитая мишень;
* `red_entire` — красная целая мишень;
* `red_broken` — красная разбитая мишень.

Итоговый датасет содержит около 500 размеченных изображений.

Данные были разделены на обучающую и валидационную выборки в соотношении 80/20.

## 2. Обучение модели

Для детекции мишеней и определения их состояния использовалась модель `YOLO11` с предобученными весами.

Модель была дообучена на подготовленном датасете в течение 250 эпох.

Метрики обучения и итоговые веса модели находятся в директории `models`.

## 3. Обработка видео

Для автоматического анализа видео реализовано Python-приложение.

Запуск:

```bash
python3 main.py <path_to_folder_with_videos>
```

Приложение принимает путь к директории с видеофайлами и выполняет следующий pipeline:

1. считывает видео;
2. извлекает кадры с заданным интервалом;
3. передаёт кадры в YOLO11;
4. определяет класс и состояние найденной мишени;
5. сохраняет результаты инференса в CSV-файл.

Исходные видео записаны с частотой `40 FPS`.

Для анализа используется каждый 20-й кадр, то есть модель выполняет инференс примерно для `2 кадров в секунду`. Это позволяет уменьшить количество вычислений без необходимости обрабатывать каждый кадр видео.

## 4. Параллельная обработка

Для ускорения пакетной обработки несколько видео могут анализироваться одновременно.

Для этого используется `ProcessPoolExecutor`:

```python
with ProcessPoolExecutor(max_workers=4) as executor:
    executor.map(run_model, args_list)
```

Таким образом, обработка различных видео распределяется между несколькими процессами.

Для каждого видео создаётся отдельный CSV-файл в директории:

```text
results/
```

Такой подход позволяет независимо обрабатывать результаты разных видео и упрощает их последующую агрегацию.

## 5. Анализ результатов с Apache Spark

После выполнения ML-инференса полученные CSV-логи обрабатываются отдельным Spark-приложением.

Для каждого видео Spark анализирует последовательность состояний мишени и сравнивает её состояние между соседними наблюдениями.

Например, переход:

```text
entire → broken
```

интерпретируется как попадание.

На основе последовательности состояний рассчитывается количество попаданий для каждого видео.

После обработки всех логов система определяет видео с наибольшей серией попаданий без промахов.

Пример общей архитектуры:

```text
                 ┌───────────────┐
                 │ Training data │
                 └───────┬───────┘
                         │
                    YOLO11 training
                         │
                         ▼
                    Trained model
                         │
                         ▼
Videos ──→ Frame extraction ──→ YOLO11 inference
                                   │
                                   ▼
                              CSV logs
                                   │
                                   ▼
                            Apache Spark
                                   │
                                   ▼
                    Hit / miss statistics
```

## Возможные улучшения

### Несколько мишеней одновременно

Текущая версия предполагает наличие одной основной мишени в кадре.

Если в кадре одновременно находятся несколько мишеней, необходимо отдельно отслеживать состояние каждой из них.

Для этого структуру результатов можно дополнить полем:

```text
target_id
```

Тогда записи могут иметь вид:

```text
frame_id, target_id, class, confidence
120, 1, red_entire, 0.94
120, 2, dark_broken, 0.91
```

Однако одного `target_id` в CSV недостаточно: необходимо также решить задачу сопоставления одной и той же мишени между соседними кадрами.

Для этого detector можно дополнить алгоритмом multi-object tracking, например ByteTrack или BoT-SORT.

Pipeline в таком случае будет выглядеть следующим образом:

```text
YOLO detection
      ↓
Object tracking
      ↓
target_id
      ↓
State history
      ↓
Hit detection
```

### Отсутствие мишени в кадре

Если модель не обнаружила мишень, для соответствующего кадра сохраняется информация об отсутствии детекции.

Это позволяет обрабатывать как кадры, в которых мишень действительно отсутствует, так и ситуации, когда detector временно не смог её обнаружить.

В дальнейшем обработку подобных случаев можно улучшить с помощью tracking и анализа нескольких соседних кадров вместо принятия решения по одной отдельной детекции.
